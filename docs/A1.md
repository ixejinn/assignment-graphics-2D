## 정점 좌표와 집의 중심

A1에서는 정점 좌표 `(0, 0)`이 화면 중앙에 대응한다. x는 오른쪽, y는 위쪽이 양수이며, 화면의 좌우·아래위 끝은 각각 -1과 1이다. 픽셀 단위가 아니다.

집 전체의 로컬 원점 `(0, 0)`이 집의 중심에 오도록 정점을 작성한다. 여기서 중심은 집 전체 외곽 범위의 중심으로 정한다. 즉 `(minX + maxX) / 2 = 0`, `(minY + maxY) / 2 = 0`이 되도록 모든 정점에 같은 오프셋을 적용한다. 지붕·벽·문·창문을 각각 원점에 맞추는 것이 아니라, 부품 사이의 배치를 유지하며 집 전체를 맞춘다. 외곽 범위의 중심은 면적 무게중심과 다를 수 있다.

A2의 TRS 모드는 이 로컬 원점을 기준으로 회전·크기 조절한 뒤, 원점을 `Object::position` 위치에 배치한다. `position`만 바꾸는 것은 정점을 중심에 맞추는 작업을 대신하지 않는다. 제공된 지붕 삼각형은 렌더링 확인용이며, 집 전체의 중심을 맞춘 완성 예제가 아니다.

| Attribute location | 입력 | 컴포넌트 | offset | Buffer binding |
|---|---|---:|---|---:|
| 0 | position | 2 | `offsetof(Vertex,x)` | 0 |
| 1 | color | 3 | `offsetof(Vertex,r)` | 0 |

`Vertex`에는 Assignment 4에서 사용할 UV인 두 float도 예약되어 있다. 현재는 0이고 enable하지 않는다. 따라서 stride를 위치+색상의 5개 float로 하드코딩하면 안 된다. `GL_FLOAT`, normalize=`GL_FALSE`를 사용한다.

## DSA와 정점 속성 연결

DSA(Direct State Access) 함수는 설정할 객체의 ID를 인자로 받는다. 버퍼에 데이터를 올리는 일과 VAO에 데이터 읽는 방법을 기록하는 일을 구분해서 작성한다.

VAO의 연결은 다음과 같이 생각하면 된다.

```text
VBO → VAO의 binding 0 → location 0: 위치(x, y)
                      → location 1: 색상(r, g, b)
EBO → VAO의 인덱스 버퍼
```

location은 shader의 입력 번호이고, binding은 VAO 안에서 VBO를 연결하는 번호다. 위치와 색상이 같은 Vertex 배열에 들어 있으므로 서로 다른 location이 같은 binding 0을 사용한다.

아래는 위치 속성 하나를 연결하는 예시다. 버퍼와 VAO를 생성하고 VBO를 binding 0에 연결한 뒤 사용한다. 색상 속성은 위 표를 보고 직접 추가한다.

```cpp
glVertexArrayAttribFormat(mesh.vao, 0, 2, GL_FLOAT, GL_FALSE,
                          offsetof(Vertex, x));
glVertexArrayAttribBinding(mesh.vao, 0, 0);
glEnableVertexArrayAttrib(mesh.vao, 0);
```

처음부터 집 전체를 만들기보다 제공된 지붕 삼각형이 보이는지 먼저 확인한다. 그다음 벽, 문, 창문을 추가한다. 사각형 하나는 삼각형 두 개로 나누면 된다. 같은 위치라도 서로 다른 색이 필요하면 정점을 나누어 사용할 수 있다.

## 완료 기준

- 지붕·벽·문·창문이 구분되어야 한다. 크기와 색은 자유이며, 그림의 꾸밈 정도는 평가하지 않는다.
- 집 전체 외곽 범위의 중심이 로컬 `(0, 0)`에 오도록 정점을 작성한다.
- immutable buffer의 데이터를 나중에 다시 업로드하지 않는다.
- 집 렌더링은 본인의 `drawMesh` 함수를 구현해 집을 그린다.

## 설명 문제와 제출

1. VBO, EBO, VAO의 역할을 각각 한 문장으로 설명하라.

    - VBO: 정점 데이터의 배열 (vertex buffer object)
    - EBO: 정점을 어떻게 이어서 삼각형을 만들지 순서를 나타내는 정점 인덱스의 배열 (element buffer object)
    - VAO: 정점을 어떻게 읽을지에 대한 설정을 저장하는 객체 (vertex array object)

2. attribute location 1과 buffer binding index 0은 어떻게 다른가?

    모두 VAO에서 다룬다.
    attribute는 하나의 정점 데이터 안에서 얼마나, 어떻게, 어디부터 읽어서 셰이더의 몇 번 location에 넘길지를 결정하고,
    binding index는 어떤 VBO를 어디서부터, 얼마의 간격을 하나의 정점 데이터로 읽을지 결정한다.

    하나의 바인딩 슬롯에는 하나의 VBO만 넣을 수 있다.
    과제에서처럼 여러 속성이 하나의 슬롯을 가리킬 수도 있고, 속성마다 다른 슬롯을 가리킬 수도 있다. 속성과 슬롯을 연결하는 것이 `glVertexArrayAttribBinding` 함수이다.

3. 정점 개수와 `glDrawElements`의 count가 다른 이유는?

    정점 개수는 말그대로 정점 데이터의 개수를, `glDrawElements`의 count는 이번 draw에서 인덱스를 몇 개 읽을 지를 의미한다.

    정점 3개씩 삼각형으로 만드는 `GL_TRIANGLES`를 예로 들면,
    
    사각형을 이루는 정점은 4개이고 사각형 하나는 두 개의 삼각형으로 그려지므로, 사각형 하나를 그리기 위해 6개의 정점 데이터가 필요하다.
    ```
      3 --- 2
      |  /  |
      0 --- 1
    ```
    사각형 0123은 삼각형 012와 023로 그릴 수 있다. 이때 두 삼각형에서 정점 0과 2는 중복되므로 6개의 정점 데이터를 각각 저장하는 대신, 삼각형을 그릴 정점의 순서(위 그림의 경우 0, 1, 2와 0, 2, 3)를 인덱스로 저장하면 정점 데이터 4개로, 두 개의 삼각형을 그릴 수 있다. 즉, 정점 개수는 4개, 인덱스의 개수는 6개가 된다.
